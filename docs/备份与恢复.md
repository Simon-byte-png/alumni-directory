# 数据备份与恢复

生产环境启用 `ALUMNI_BACKUP_ENABLED=1`，使用独立的 `ALUMNI_BACKUP_KEY`（32 字节随机值，编码为 64 个十六进制字符）。密钥只放在服务端环境和私有恢复文件中，不能提交 GitHub、放入网页或发送到群里。

## 保存和保留规则

- 每次数据库状态更新生成独立的加密文件：`alumni-backups/<primary 或 analytics>/<日期>/<时间和随机编号>.alumni-backup`。同一天、同一秒的更新也不会覆盖旧文件。
- 文件存放在 CloudBase 云存储中，不依赖数据库或容器本地磁盘。使用 AES-256-GCM 加密并校验完整性，上传后下载回读、解密比对成功，保存请求才返回成功。
- 在替换尚未确认有备份的旧版本前，先备份旧版本。数据库已提交但新备份未确认时返回明确错误，保留页面内容；下一次修改不能用旧内存覆盖数据库的新资料。
- 每次服务启动（包括部署新版本）也会生成两份当前状态备份。启动备份失败时不开始接收请求，避免静默关闭保护。
- 程序没有清理备份、覆盖历史备份或删除云备份的操作。用户删除过去经历或管理员删除账号，只删除当前数据库中的记录，历史备份继续保留。
- 用户选择长期保留，不启用不可提前解除的云端对象锁。需要保持云存储账号有效和足够额度；不要给备份目录设置自动删除规则。云平台管理员仍有手动删除的权限，不能把这套机制描述成绝对无法删除。
- 本地开发使用 JSON 状态文件时，另在相邻 `backups/` 目录生成独立文件，权限 0600；这些文件由 `.gitignore` 排除。生产保护使用云存储，不把容器磁盘当作持久备份。

离线副本放在部署方自己的私有目录，目录权限 0700，文件权限 0600。不要把这个目录放进 Git。本地完整副本在发布前后导出；每次在线更新的自动副本保存在云存储中。

## 未保存的填写内容

注册表单、本人资料输入时自动暂存浏览器草稿，不暂存密码或答题答案。本人草稿按账号隔离，重新打开后由用户选择恢复，不直接覆盖服务器最新资料。只有保存确认成功或正式开户成功才自动清除对应草稿；主动退出登录清除该账号草稿，避免共用设备泄露资料。浏览器草稿不等于服务器备份，换设备、清理浏览器数据或禁用本地存储会影响恢复。

## 导出完整备份

在已经安全配置正式服务环境变量的进程中执行（不要把密钥写进命令历史）：

```sh
npm run backup-state -- '/绝对路径/私有备份目录'
npm run verify-backup -- '/绝对路径/私有备份目录/full-....alumni-backup'
```

导出包括 `primary`（账号及密码哈希、题库、名册、个人资料、经历、申请、锁定）和 `analytics`（访问统计）。同时生成云端副本和本地校验清单。每次导出都生成新文件，不覆盖前次导出。`verify-backup` 解密、检查重复身份并恢复到临时私有目录核对内容，不修改正式数据库。

## 恢复正式环境前

1. 暂停写入，先导出故障现场，保留所有旧备份。
2. 使用独立恢复密钥解密选定文件，在隔离数据表核对账号、资料、名册和统计，确认备份时间及缺失范围。
3. 确认恢复版本后才替换正式数据；不要把仅含 `analytics` 的备份当成全部数据，也不要重新生成一套空用户表。
4. 正式恢复时清除过期登录会话、增加会话版本，要求用户重新登录，避免旧备份中的会话意外恢复有效。密码哈希保留，无需修改成员密码。
5. 重启服务，检查数据库、备份文件、登录、本人资料和管理员视图。
